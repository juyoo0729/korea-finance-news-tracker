# 📰 Korea Finance Tracker

> 한국 경제 뉴스를 자동 수집·분류하고, **수학(미분) 기반으로 "오늘 살펴볼 만한 종목 후보"를 추려주는** 모니터링 도구
> OpenAI GPT + 공개 시장 데이터 활용

## 🎯 프로젝트 소개

부트캠프 학습 중 만든 개인 프로젝트입니다. 처음엔 한국 경제 뉴스를 **자동 수집 → 산업 섹터 분류 → LLM 요약**하는 모니터링 도구로 시작했고, 이후 **시장 데이터를 받아 "오늘 검토할 만한 종목 후보"를 점수화해 추려주는 기능**으로 확장했습니다.

핵심 설계 원칙은 처음부터 하나였습니다.

> **"사세요"가 아니라 "후보입니다."**
> 이 도구는 매수를 추천하거나 주가를 예측하지 않습니다. 수많은 종목 중 **조건에 맞는 소수만 걸러서, 왜 후보인지·무엇을 주의해야 하는지 사람이 읽을 수 있는 말로 정리**합니다. 최종 판단은 전적으로 사용자의 몫입니다.

즉 점쟁이가 아니라 **체로 걸러주는 비서**를 목표로 했습니다.

## ✨ 주요 기능

### 1. 시장 데이터 대시보드
- `FinanceDataReader`로 KOSPI/KOSDAQ 전종목 스냅샷 수집
- 등락률 / 거래대금 / 시가총액 기준 TOP 종목 테이블

### 2. 🧮 오늘의 후보 종목 (미분 기반 2단계 스코어링)
프로젝트의 핵심 기능입니다. 전종목을 무겁게 분석하지 않고, **싸게 거른 뒤 좁혀서 깊게 보는** 2단계 구조로 설계했습니다.

**1단계 — 절대 기준 필터링 (전종목, 가벼움)**
- 제외 필터: 시가총액 과소(잡주)·거래대금 과소(유동성 부족) 종목 제거
- 등락률 점수: 적당한 상승은 가점, **급등(+10% 이상)은 추격매수 위험으로 감점**
- 거래대금 점수
- 점수 상위 약 30개만 2단계로 전달

**2단계 — 일봉 기반 보강 (후보 30개에만, 무겁게)**
- 최근 60거래일 일봉(`fdr.DataReader`)을 후보 종목에 한해서만 조회
- **1차 미분(속도)**: 가격 추세의 방향과 세기
- **2차 미분(가속도)**: 하락이 꺾이는 변곡점 → **"바닥 반등 후보" 포착**
- **20일 이동평균선** 상회/하회
- **RSI(14)**: 과매도(반등 가능성) / 과열(조정 주의)
- **20일 모멘텀**

노이즈를 줄이기 위해 원본 종가가 아닌 **5일 이동평균에 미분을 적용**합니다. 각 지표는 점수뿐 아니라 **"하락세가 꺾이고 반등 신호 — 바닥 변곡점 가능성"** 같은 한국어 설명으로 출력됩니다.

### 3. 오늘의 인기 주제 TOP 3 (임베딩 클러스터링)
- `sentence-transformers`로 헤드라인을 벡터화 후 `AgglomerativeClustering`으로 유사 제목 자동 그룹화
- 클러스터 중심에 가장 가까운 제목을 대표 헤드라인으로 선정
- 오늘 뉴스에서 가장 많이 다뤄진 주제 3개를 한눈에 파악

### 4. 다중 소스 뉴스 수집
- 네이버 금융 전체 뉴스 크롤링, 중복 자동 제거
- 한경 RSS·종목별 소스는 코드에 유지(주석 처리) — 필요 시 즉시 재활성화 가능

### 5. 산업 섹터 자동 분류 (하이브리드)
- 1단계 키워드 사전 매칭 → 미해결 건만 2단계 LLM 분류, 결과 캐싱
- 지원 섹터: 반도체, 자동차, 이차전지, 바이오/제약, 금융, 게임/엔터, 조선/방산, 철강/소재, 부동산/건설, IT/플랫폼

### 6. LLM 요약
- OpenAI GPT(`gpt-5.4-mini`)로 헤드라인 묶음을 핵심 3줄로 요약
- `OPENAI_API_KEY` 환경변수 필요 (`.env` 파일 지원)

## 🚀 시작하기

### 1. 저장소 복제 및 패키지 설치

```bash
git clone https://github.com/juyoo0729/korea-finance-news-tracker.git
cd korea-finance-news-tracker
pip install -r requirements.txt
```

### 2. API 키 설정 (뉴스 요약·LLM 분류용)

프로젝트 루트에 `.env` 파일을 만들고 OpenAI API 키를 입력합니다:

```
OPENAI_API_KEY=sk-...
```

> API 키가 없어도 후보 스코어링·뉴스 수집·임베딩 클러스터링은 정상 동작하며, LLM 요약·분류 기능만 비활성화됩니다.

### 3. 실행

```bash
streamlit run dashboard.py
```

브라우저에서 `http://localhost:8501` 자동 열림. 화면을 내리면 **"🎯 오늘의 후보 종목 TOP 10"** 섹션을 확인할 수 있습니다.

**CLI (뉴스 전용)**

```bash
python news_tracker.py --keyword 반도체 --summarize
# 모델 지정 (기본: gpt-5.4-mini)
python news_tracker.py --keyword SK하이닉스 --summarize --model gpt-5.4-mini
```

## 💡 개발 과정에서 배운 점

이 프로젝트의 진짜 가치는 도구 자체보다 **만들면서 부딪힌 문제들을 풀어가는 과정**에 있었습니다.

### "임의의 점수표"에서 "수학적 근거"로
- 초기 점수는 `0~3% 상승이면 +15` 처럼 **직접 손으로 정한 숫자**라, 거래대금 충분한 종목이 전부 동점(30점)으로 뭉치는 문제 발생
- 단순 상대 순위(rank)로는 "오늘 이미 오른 종목"만 잡혀 추격매수 구조가 됨
- 해결: **가격 그래프의 미분**을 도입. 1차 미분으로 추세를, **2차 미분으로 하락→반등 변곡점**을 포착해, 오늘 안 올랐어도 바닥에서 돌아서는 종목까지 후보로 잡도록 설계

### 무거운 작업은 좁혀서 — 2단계 구조
- 전종목(2000개+)에 일봉을 일일이 요청하면 느리고 차단 위험
- 해결: **1단계로 가볍게 30개로 거른 뒤, 그 30개에만** 일봉을 받아 깊게 분석

### "코드가 있다"와 "코드가 돈다"는 다르다 — 무음 실패(silent failure) 디버깅
- 2단계 로직을 추가했는데 화면 결과가 1단계와 **완전히 동일**
- 원인: 일봉 조회가 `try/except`에서 예외를 조용히 삼키고 1단계 점수로만 fallback 되고 있었음
- 해결: 예외를 출력하도록 바꿔 실제 원인을 추적 → 코드 존재가 아니라 **실행 결과를 직접 확인**하는 습관의 중요성을 체감

### 데이터를 보고 기준을 조정하는 일 (모델 튜닝)
- 속도 −0.12%/일짜리 횡보 종목까지 "반등 신호"로 잘못 표시되는 문제 → **반등 판정에 하락폭 임계값** 도입
- RSI가 설명에는 나오지만 점수엔 약하게 반영 → 과매도 구간에 명확한 가점 부여
- 결과를 눈으로 보고 "이건 이상한데?"에서 출발해 기준을 다듬는 과정은 **하이퍼파라미터 튜닝과 동일한 사고**였음

### 한국어 뉴스의 별명/이형 표기
- "삼성전자"가 헤드라인에선 "삼전", "50만전자"로 더 자주 등장 → 별명 사전 구조 도입
- LLM 백엔드는 `llm_client.py`로 분리해 요약·분류 모듈이 모두 같은 진입점을 공유, 모델 교체가 한 곳에서 이루어지도록 설계
